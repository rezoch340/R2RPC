## 大块(核心能力)

### ✅ #1 日志保留/裁剪
`request_logs` 是日志表(硬删)。按天清理(默认 3 天)+ 每 `(group,action,client)` scope 只留最新 100 条(窗口函数),挂现成 5min 维护 worker(`retention-sweep`)。阈值走 zod 配置。
> **聚合表按天清理**(`AGGREGATE_RETENTION_DAYS`,§2.8 item 3)暂缓 → 并入 #3(表还没建)。

### ✅ #2 设备接入模型重构(epic)
**设计定稿:** `docs/superpowers/specs/2026-07-09-device-model-redesign-design.md`。把"设备持久态"扩成一次接入模型重构:device token 自注册(SDK 自生成 id)、`groups→projects` 改名、删 client-login/clients/client_groups。设备 project **继承 device token**(建时勾定,天然绑定,不自报能力)。在线态走 Redis 热 + PG(`devices`)冷持久。
**子项(各自独立 spec/PR):**
- **2a** ✅ rename `groups→projects`(纯机械,先做,后续全用新名)。
- **2b** ✅ device token:`device_tokens` + `device_token_projects` + CRUD + 在线设备数。独立无依赖。
- **2c** ✅ 设备自注册 + 删 client-login(WS 网关改 device-token 鉴权 + 自生成 id → upsert `devices` + presence;删 `clients`/`client_groups`/client-login;改 RBAC/seed/smoke)。**最大一块。**
- **2d** ✅ 设备持久态:stale 扫描 worker + 列表/详情 API(`read/device`)+ platform/ip/extra 落齐(并入原 #11)+ `status` 口径。
**解锁:** #3(device 日聚合)、#8。

### ✅ #3 指标聚合体系(3a + 3b)
- **3a ✅ 聚合管道**:两日聚合表 `device_daily_metrics`/`rpc_daily_metrics`(drop `metrics` 空壳)+ 完成累加(挂 `RequestLogProcessor`,writeSpine 首插判去重)+ 重启对账(worker 启动从 request_logs 重灌最近 N 天)+ 聚合表按天清理(30 天,承接 #1 暂缓项)。
- **3b ✅ 读视图**:`GET /metrics/weekly`(近7天设备)+ `GET /metrics/trend`(按天补零 + successRate)读聚合表 API;`overview` 不动(扫 raw,retention 封顶 3 天、成本有界)。**GroupSummary/GroupInfo 归 #8**(有设备维度,不在 3b 重复)。
**依赖:** 3b 依赖 3a;整体依赖 #2(设备聚合口径,已就绪)。

### ✅ #4 maxInFlight 在途并发限流
设备 WS 连接 `?maxInFlight` 自报,服务端夹到 `[256,1024]`(默认 512),存 Redis `device:maxinflight:{cid}`(TTL 随 presence)+ devices 行 + welcome 回带。在途计数 Redis `device:inflight:{cid}`:invoke 选到设备后 `tryAcquireSlot`(INCR,超上限自减回退→`rejected`/429),派发段 try/finally `releaseSlot` 保证每 acquire 精确一次 release;连接 reset + 下线 offline 清理防泄漏。
> 组饱和(多设备轮询跳过满设备)已补齐:invoke 无 `?clientId=` 时走 `PresenceService.pickOnlineAcquire`,组内 RR 从游标起轮一圈、占第一个未满设备的槽,全满才 `rejected`/429(`功能组内设备在途任务均已满`);指定 clientId 路径仍单设备占槽。见「完成记录 2026-07-09 · #4b」。

## WS 协议健壮性

### ✅ #5 服务端主动 ping + 读超时
按 socket 每 5s 主动 `ping`;活动(message/pong)超 20s 无更新即 `terminate()` 判离线。下线清 timer。

### ✅ #6 帧限制 + 拒分片 + deadline
单帧 **4 MiB 上限**(`@WebSocketGateway maxPayload`,超限 ws 自动 close 1009);job `deadlineAt`(=invoke startedAt+timeout),`deliverLocalJob` 发送前 guard 丢弃过期任务。
**拒分片(FIN=0)** 已补齐(见 #6b):网关 `handleConnection` 首行实例级包裹 `socket._receiver.getInfo`,帧头解析后 `_fin===false` 即用 ws 自身错误链路以 **1009** 关闭整条连接(控制帧强制 FIN,故只命中数据帧分片);依赖 ws 8.21 内部字段,升级失踪则 fail-open 记 error。

## 小项

### ✅ #9 监控筛选下拉选项
`GET /monitor/request-options?project&action&clientId`(`read/monitor`)→ `{projects, actions, clientIds}`(均 string[])。从 `request_logs` 去重取三类候选,**联动过滤**(每维排除自身、按其余已选维约束),实体存在要求:project inner join `projects`(alive)、client inner join `devices`(alive),action 无实体不约束;每类封顶 200。对齐老系统 `RequestFilterOptions`。

`app_audit_json`，Monitor 详情懒加载返回，PG 脊柱和列表不包含审计。

### ✅ #13 管理员账号隔离与改密
新增 `PATCH /users/:id` 资料修改和 `PATCH /users/:id/password` 改密。
`AdministratorAccountPolicyService` 以 JWT 请求者编号保护 `isRoot` 目标：非本人一律 403，
且统一覆盖资料、密码、enabled、软删除和 RBAC 用户角色绑定/解绑。用户响应显式选择安全字段，

### ✅ #14 权限组

permissions；新增权限组编辑、用户权限组查询和请求体关联入口，旧 URL 入口继续兼容。
`read/rbac` 可委派读取，全部 RBAC 写操作叠加 `RootGuard`，只有种子管理员可执行；
`manage/rbac` 不能绕过身份闸。组内权限使用固定批量查询组装，无 N+1，无数据库迁移。

### ✅ #15 系统操作审计日志

白名单 metadata、HTTP 结果、IP 和时间。登录成功/失败、全部 JWT 控制面读取和 Guard/路由

`GET /system-logs` 使用 `read/system-log` 筛选分页。日志不保存密码/token 明文，不提供修改
或删除 API，也不与 RPC 请求日志、设备 AppAudit 混用。
