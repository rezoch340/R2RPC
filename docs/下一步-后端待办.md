# RER0RPC 后端下一步

> 更新日期：2026-07-24。后端功能 backlog #1–#13 已收官；本文只记录发布就绪和非阻塞硬化工作。

## 当前基线

- API/Worker 双进程已完成。
- 设备模型、三套鉴权、管理员账号隔离与改密、RPC、AppAudit 日志 Step、指标、限流和 WS 健壮性已完成。
- OpenAPI 已导出。
- 黑盒完整性冒烟为 131 项，全部通过 HTTP/WebSocket，不直连数据库、Redis、Manticore 或应用内部服务。
- 活跃源码与测试已完成变量命名/复杂度审计；`pnpm lint:check` 强制完整变量名、复杂度 ≤ 10、嵌套 ≤ 3、单函数语句 ≤ 40。

## P1：边界硬化

1. `clientId` 按 device token 隔离，避免不可信设备冒用。
2. `rpc/clientQueue?clientId=` 校验 client 是否属于 token 授权 project。
3. 限制 token 列表回显明文的后台权限和审计策略。
4. 为用户权限查询增加短 TTL cache-aside，并在 RBAC 写路径失效。
5. 为 WS 内部 `receiver.getInfo` 兼容性增加升级回归测试。
6. 设备 SDK 按 `docs/device-app-audit.md` 提供通用 Recorder，避免各设备手拼 Step。

## P2：可观测性与运维

1. Prometheus 指标。
2. 结构化日志与 requestId。
3. BullMQ backlog、failed/dead-letter 告警。
4. PostgreSQL/Manticore 保留任务运行结果审计。
5. 多 API 实例跨节点黑盒测试。

## 测试规则

- `pnpm smoke` / `pnpm test:e2e` 只能访问 HTTP/WS。
- E2E 禁止导入数据库、Redis、Drizzle 或 Nest 应用内部 service。
- Worker 结果通过 `/monitor/*`、`/metrics/*` 等公开读接口观察。
- 无公开控制面的底层算法检查放在 `pnpm test:integration:*`，不得称为 E2E。

## 下一项建议

优先实现 **P0 CI + 健康检查**。两者能把当前“功能完成”推进到“可持续发布”。
